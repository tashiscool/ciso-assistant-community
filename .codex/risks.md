## Additional workflow boundaries to retain

- Core framework/requirement catalogues, GRC managed knowledge and imported library packs are distinct stores; similarly titled screens do not necessarily share objects.
- Shared `/core/modules` JSON records provide breadth, but do not reproduce every mature legacy ORM workflow or regulatory validation.
- Assessment workbench/Home can fail as a unit when one parallel dependency is unavailable/unauthorized. Some UI actions lack corresponding fine-grained write gates, even where the backend rejects writes.
- Evidence creation offers multiple provider names; the non-AWS form does not fully configure each provider. Generic `custom_http` supplied-input normalization is distinct from live HTTP collection.
- Current quantitative retrigger changes portfolio summaries independently of scenario economics. A complete legacy simulation port needs explicit scope and tests.
- Report previews can use examples/unfiltered fallback records. Dashboard previews can be explanatory tiles rather than generated charts. Native file validity needs parser/renderer checks.
- Questionnaire file inputs are reference text; public rendering simplifies some question types. The public handler now enforces `loginRequired` using a same-tenant D1 session; native file upload remains a separate capability.
- Setup policy persistence is distinct from global application/enforcement. SSO secrets/provider credentials, email settings, token inventories and evidence config require a targeted storage/redaction/access review before live use.
