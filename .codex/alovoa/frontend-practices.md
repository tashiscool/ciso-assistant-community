## Recommended implementation order

1. **Implemented:** local mutation-based QA is loopback-only and collected runtime/API/network diagnostics now fail its result. The initial responsive false-pass gap is fixed, with synthetic regression coverage.
2. **Implemented:** dependency-free transport response/error helpers and focused tests preserve valid JSON, public methods, credentials/identity and base/body behavior. Empty success is explicitly undefined only for 204/205; malformed or empty 200 is a typed protocol error.
3. Make non-auth browser preferences resilient to blocked/quota storage; use the existing key names and behavior. Auth identity storage needs separate security review.
4. Add a small source/action/readback ledger and executable regression scenarios for current defects: anonymous questionnaire parameters, mobile navigation/keyboard/focus, response contracts, stale record selection, failed jobs and false-success actions.
5. Apply response validation and stale-result protection one existing feature adapter/workbench at a time, with canonical saved readbacks. Do not wrap every response in a made-up `ok` convention or redesign service contracts.
6. Measure bundle/lifecycle costs and then consider a bounded lazy-route improvement; avoid new query/form/state libraries and broad refactors without approval.

Applicability categories used below:

- **Adopt:** a bounded implementation or quality pattern that fits existing dependencies and source semantics.
- **Adapt:** useful practice, but needs domain-specific scope/response/error assumptions and focused tests.
- **Review:** requires an architecture/API/persistence/auth/access-control/dependency decision before implementation.
- **Already present:** retain/test what Regovise already does rather than duplicate it.
- **Do not transfer:** sibling-specific or weaker than the actual target requirement.
